# 已确认要求的逐项展示（2026-10-30）

基线：feature/human-review-completion，HEAD 701700c；保留已有未提交的人工审核闭环／PDF 改动。本轮只修改前端读取展示，不切换分支、不重启服务、不自动提交或推送。

## 实现

- “选择营地的原因”主表从该方案 confirmed_context.requirements 的偏好、必须条件及 profile_snapshot 的同行特殊需求逐项建行。保留目的地、人数、交通基础信息；不读取当前个人资料或尚未确认的表单。
- 逐项标识偏好／必须条件／同行特殊需求，结果使用“资料符合”“未满足”“待核实”“资料冲突”。同一设施兼有偏好与必须条件时合并一行，保留全部类型标识。
- 用餐方式及“不使用营火”属于行程行为／专项检查，主表保留用户选择，结果写“另见专项检查”，不凭选择或营地允许用火就冒充正式安全通过。未知历史要求原样显示、待核实，不新增自动解释能力。
- 原筛选理由中的精确已保存事实继续可读；缺少偏好反馈时，只有服务端按原确认快照 source_catalogue.json 摘要发出的精确 campsite_catalogue_id，才允许读取同一固定版本的前端静态目录。旧版本或无目录身份不借用新资料，缺少来源保持待核实。没有读取实时信息、重新调用模型或补写历史保存内容。
- 示例：Lane Cove 的“安静”资料未知，显示待核实；“允许携带宠物”偏好显示未满足；厕所／淋浴显示资料符合。这里的偏好不满足不会自行变成硬性 blocker，也不自动取消真实要求或改变推荐结果。
- 未选择的厕所、淋浴、饮用水放在“其他营地配套”；已选设施不重复列出。保留营地费用、接入说明和原始理由／模型意见折叠记录。
- “记录 → 本次需求”补齐所有已确认的偏好与用餐方式、必须条件、同行特殊需求。说明这是本方案快照；缺失的旧清单与明确空清单分开表达。当前／历史／最终快照／审核复用展示，不修改原内容、评估、审计或哈希。
