## 用户流程

1. 用户填写日期、人数、预算、条件及交通方式。汽车保留真实车辆数量、每车座位及可用确认；不要求用户提前规划营地路线。
2. 系统先按营地资料中的交通可达标记和其他已确认条件筛选。未知可达信息不能当作可以到达。汽车继续支持明确登记的停车场步行接入，不将停车场接入说成车辆可直达帐篷位置。
3. 无匹配时，说明不满足／待核实的条件，提供“修改交通方式”和“核对并调整本次需求”。由用户明确选择，沿既有同系列后继流程更新，不擅改交通、日期、预算或需求。
4. 选定营地后，方案展示交通依据、模拟费用和出发前待确认事项。公共交通不生成虚构班次、末班车、订票或接驳细节。

Sydney 2.2 新运行不再把 `transport_itinerary`、`fire_free_meal_plan` 当作个人拥有的装备，也不要求录入“预计总路程”。旧资料中的这些值保留，旧计划记录可折叠回看；新政策不将它们当作有效路线或装备证明。

自炊仍核对真实炉具、燃料、炊具等适用要求；本轮新政策明确要求自炊炉具，不让“营地允许营火”替代实际烹饪安排。即食餐食无需填写一份虚拟无火餐食计划。禁火、安全证据、装备容量、审批及最终保存守卫继续独立生效，模型不能清除硬性缺口。炉具和燃料的首次准备提示、草稿规则预检查继续保留。

## 模拟出发地与距离扩展

用户已明确选择固定“悉尼市区”模拟出发地。新增独立文件 `data/transport/sydney_city_v1.json`：

- 版本 `sydney-city-demo-distances-1`，出发地 ID `sydney_city_demo`。
- 10 个营地记录，正整数为单车往返模拟公里数；没有来源的记录为 null。数值是本项目虚构的测试假设，**不是实测道路距离、实际路线或时间**。
- 单营地行程的累计车辆公里数＝该营地单车往返公里数 × 已确认车辆总数；不会再乘同行人数或住宿天数。燃油／停车费用继续使用已有费率及整数分／Decimal。
- 只有全部相关车辆数量、单位和可用确认明确，且汇总与交通字段一致时才计算距离。座位未知仍不能得到运输容量通过；距离来源不足、跨多个营地或未知费用不补零。
- 新文件创建日期单独登记为 `created_on=2026-10-27`。`provenance.source_date=2026-10-07` 沿用共享 DTO 固定的虚构数据来源标签日期，不能解释为本文件的创建日期或实际交通调查日期。
- 原三个封存数据包不修改。新文件由严格解析器读取，拒绝重复字段、重复营地、非整数／负里程及非模拟来源，核对营地 ID 全覆盖。

## A 接手与手工验收

交付须同时包含新距离文件、解析／注册、政策分流、后端投影和前端接线。A 无需新迁移编号，重点复核运行身份、恢复和最终快照读取；不要只拣前端隐藏字段。

本轮未调用真实校园模型，未修改个人环境文件、密钥、原用户数据库或封存数据，也未重启正在运行的服务。后端重启后再刷新网页才会使用新能力。

建议先用演示模式手工验收：

1. 公共交通：只选方式，不写路线或添加虚拟计划，核对需求并启动；查看匹配营地、模拟往返费用和出发前待确认说明。
2. 自驾：登记不同座位车辆并确认可用；启动后查看选中营地的模拟累计公里数及费用。增加一辆实际确认车辆后，沿同系列更新，核对累计里程和停车费变化。
3. 无匹配条件：查看具体原因，取消时不执行；明确修改后才新建同系列检查。新建独立出行仍需明确操作。
4. 自炊与即食分别检查；虚拟计划不应成为待办，自炊缺炉具／燃料仍提示，缺报价仍不能当作零费用。
5. 查看旧运行、审核页及最终快照；旧记录不变，普通用户无模型诊断。仅保存个人资料、查看历史或刷新不触发推理。

未实现实时路线／班次／票价、精确交通时长、多出发地、多营地分段路程、订票，以及步行／其他交通策略；不宣称已生成这些事实。活动推荐仍受既有数据和行程协议限制，本轮不新增活动路线引擎。
