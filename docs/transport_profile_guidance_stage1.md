# 交通支持阶段一：资料提示与定位修正

日期：2026-10-27。起点：main / 043311c；保留工作区已有的物流诊断、费用协议和前端展示修改。

后续已实现公共交通最小支持，见 [最小公共交通交接](minimal_public_transport_handoff.md)。下文“正式规则待后续实现”保留阶段一当时的范围；当前托管 v2 新运行会使用后续文档登记的交通子策略。

## 范围

修复公共交通资料页沿用原检查的车辆数量提示，以及“前往首个待补充位置”定位不存在的 vehicle-count 元素的问题。

- 当前交通方式不是 CAR 时，旧车辆数量、车辆库存和行车公里缺项不再成为表单填写提示，旧链接也不会定位这些字段。
- 不因这些旧问题自动添加空白车辆记录；已经保存或填写的车辆记录保持原值，不删除、不清零。
- CAR 继续提示数量、座位、确认状态。交通连接计划等其他真实缺项继续提示。
- 摘要把车辆汇总提示映射到可编辑数量框，与已有数量提示去重；车辆单位不存在独立编辑框，不再跳转到不存在的单位控件。
- 导航跳过不存在或禁用的目标，定位后执行聚焦和滚动；所有目标均不可用时显示明确反馈。无待补充提示、读取中或读取失败时不显示该跳转按钮。
- 当前表单填写完成与正式方案检查通过分开表达。原确认资料、原评估、eligibility、审核、最终记录与恢复输入不变。

## 规则与接口边界

本轮只修资料页及导航，不新增交通策略、接口、DTO 字段或数据库迁移，不改规则身份、Prompt 或封存数据。

这不是将非 CAR 的 vehicle_count 从 null 默认改为 0。现有 v2 gear-18 等表达式可能仍在正式评估中产生未知 vehicle_count 输入；本轮不会清除该已保存问题，也不把表单无提示当作解决它。该规则变量的“本次使用车辆”语义及版本兼容需在后续交通策略契约中明确，不能由前端填造事实或放行。

PUBLIC_TRANSPORT 的实际连接核实、WALKING/OTHER 的正式支持属于后续阶段。页面有选项不等于本轮已实现对应完整后端能力。

## 手工复测（不触发模型）

1. 从有车辆缺项的方案进入资料页；选择公共交通，确认不再显示车辆数量红框、虚假的待补充计数或自动新增车辆。
2. 保留公共交通连接计划的真实空白／未确认项，点击定位，应聚焦对应的数量或确认输入框。
3. 改为汽车，清空数量、座位或确认；逐项填写，验证数量与总数不会重复计数，定位能到真实输入。
4. 表单补完后，确认只提示保存／核对后重新检查，没有“正式检查通过”或原方案问题已解决的声明。
5. 仅保存、返回、刷新均不应自动启动模型；原方案应仍显示原确认资料与正式结果。
