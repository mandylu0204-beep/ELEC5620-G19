## 修复与诊断结论

- 当前基线独立复现 missing_evidence：第二轮请求 24505 bytes，约 30303ms 后代理返回 HTTP 502，95 bytes 错误体含 upstream 标记。未知帐篷的短提示诊断也在约30340ms返回相同错误摘要。确认收到的是代理 HTTP 错误，而非本地 JSON 校验失败；**具体上游根因仍需维护方日志，不能宣布已经修复校园服务器或证明固定30秒超时。**
- 另一个独立风险：旧提示搭配诊断 low 参数，三轮均 HTTP200，但最终方案的理由/摘要未与已计算方案逐字一致，被原严格校验拒绝。不能把 HTTP200当作完整成功。
- 提示明确模型只做供给方式与费用优先级选择，不计算预算或补猜未知事实；给出准确 JSON 信封，要求简短理由、简短摘要。
- 计算反馈提供 `evaluated_proposal`，要求最终原样返回。压缩反馈中的重复装备事实和来源；第一次读取的完整事实不变，每项计算结果、费用与预算分配保留。正式保存仍是完整 plan，不是压缩对象。
- 新增显式、可选 `ELEC5620_REASONING_EFFORT=low`，只转发已实测被代理接受的 low；未启用时字段不发送、不进入旧 public identity。启用时进入模型公开身份和配置指纹，不能通过隐藏 transport 参数改变真实执行。默认未启用，不接受任意模板参数。
- 模型失败增加脱敏的物流轮次、角色总耗时及消息 UTF-8 字节数；不记录正文、凭据或私有推理。

共享 DTO/schema、AgentPort、A24 正式保存接口、确定性规则和存储 payload 验证版本不变；没有改规则来放行、另建数据库、伪造 trace 或补跑已保存物流。提示/schema摘要的现有机制登记新的 wire 提示身份。回归覆盖旧提示身份的已存审计和最终快照可回读。

## 由用户/A继续：最少真实调用的复测步骤

用户要求控制token消耗，B曾停止新增真实调用；之后经用户再次授权，已完成上述补测并停止调用。以下保留为A需要独立复核时的可选步骤，并非仍有三项未完成；不要求重复付费验收。

1. A复核本轮diff与可选参数，约定共同验收配置。校园网络/VPN和本地密钥按原配置使用。
2. 在本机 `.env.llm.local` 设置以下非密钥项，或在启动进程环境设置；不提交个人文件：

   ```dotenv
   ELEC5620_MAX_COMPLETION_TOKENS=4096
   ELEC5620_REASONING_EFFORT=low
   ELEC5620_MAX_ATTEMPTS=1
   ELEC5620_MAX_TURNS=3
   ```

   上面的1次尝试/3轮是**省额度复测配置**，不是本轮2次/4轮的同身份配置；单次失败即停止并保存错误，不连续点恢复。新PLAN/REVISE通常5次completion（规划2、物流3），按每角色最多3轮计算严格上限6次；同版本重评最多3次物流completion，不再调用规划。实际token数由响应usage决定，不能事先承诺账单。
3. 提示、low或限制变化会改变登记身份。旧FAILED运行不要修改配置后强行RETRY；复制原需求、重新解释和明确确认，启动新运行。保留旧失败证据，不清库。已保存物流的同身份恢复不得补跑模型。
4. A如需要独立复核，先查看补测证据；必要时才限额复测REASSESS或road_closure，核对原规划trace/版本、新物流audit及保存守卫。浏览器只查看已生成结果，不重复生成。已完成运行停止/重启后只读查看记录不调用模型。
5. 若再次502，停止付费重试：保留时间、轮次、耗时、公开配置与HTTP状态/关联编号，请校园代理维护方查upstream日志。不要发送密钥、原始请求头或私有推理。全部联合复测确认后再决定PR #5合并；本轮仍保持PR未合并。
