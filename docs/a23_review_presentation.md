# A23：人工审核队列与决定展示

日期：2026-10-14。基于 A22 `6833b8a`。

## 改动

- 审核队列使用营地、日期、提交者、费用及风险卡片，支持待人工判断与待处理问题分类；未知金额保持未知。
- Founder 详情默认打开安全依据，再提供批准、要求修订、拒绝三个决定，必须填写具体理由。批准受阻时显示原因并禁用对应选项。
- 同一评估上下文刷新保留未提交理由；运行、输入指纹或评估变化后清除旧草稿。提交保留原有 CSRF、CAS 与幂等命令键。
- 保存后显示实际审核结果和理由；批准仍需露营者显式最终保存。当前有效批准显示“审核已批准”，原风险与评估结果继续展示。重新评估不能沿用旧批准；历史最终记录保留当时的审核。
- 安全证据 AVAILABLE 显示为“已提供”，与道路通行状态分别展示，避免把已有道路关闭证据误读为道路可用。
- 队列 GET 增加只读 summary 和 owner_display_name；详情 GET 增加 owner_display_name。摘要仅取当前运行绑定版本的已保存产物，不返回完整资料或运行 scope。路由回执在运行完成前产生的 RUN_NOT_SUCCEEDED 提示不再出现在已完成队列，当前版本状态单独显示。

共享 schema 1.0、数据库结构、A/B 持久化端口、审核提交签名、权限及最终化守卫、校园模型接线、封存数据包均未修改。B 无需修改 Adapter 或 Agent 接口，更新 main 即可。

## 验证

- `backend/tests/test_review_queue_summary.py` 与 `backend/tests/test_reviews.py`：19 项通过，包括当前运行摘要、未知金额、重评不混入旧风险或费用、角色限制及已有审核守卫。
- 共享 schema 导出检查、前端类型检查和生产构建、`git diff --check` 通过。
- 实际浏览器、HTTP 与 SQLite 验证使用独立数据库。高风险可审核场景取自独立 v1 规则测试输入，完整安全证据中加入既有规则支持的极端高温描述；道路关闭取自封存 v2 官方 road_closure 输入，日期为 2027-04-10 至 12。本轮模式为 deterministic_demo，没有调用校园模型，也没有修改个人配置或用户数据库。
