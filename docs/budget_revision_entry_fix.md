# 超预算待办：保持预算并进入降费修订

日期：2026-10-27。开始修复前已提交现有内容：7991458（物流诊断与费用协议）、86869fd（交通最小支持及资料提示）。本轮预算入口修复保持未提交。

## 用户行为

- 超预算待办现在提供两个独立入口：“保持预算，寻找更低费用方案”和“调整本次预算”。
- 前者只展开并滚动到已有修订面板，聚焦修改目标，预选 cheaper campsite；不发送写请求，不在导航时调用模型。
- 面板显示原确认预算和真实能力边界。用户明确点击“确认保持预算并修订方案”后，才复用原 REVISE 接口提交。修改预算入口仍进入同一次出行的需求更新／核对流程。
- 修订目标受父页面控制，避免展开面板后仍默认“更换营地”。自定义反馈没有因准备降费目标而被清空。
- 当前修订不可用时不显示可执行的降费按钮；历史、最终快照、审核、已被取代方案及进行中的运行不提供该入口。是否可修订继续来自服务端 revision_available，不使用 display_status 授权。

## 能力范围

复用既有 POST /plans/{id}/revise，feedback 为 cheaper campsite；请求不新增预算覆盖字段。原命令 key、版本／运行并发校验、模型审计、恢复、完整费用计算、安全检查和最终保存守卫不变。

当前策略寻找单晚营地费更低的营地，然后重新计算完整结果，不承诺总费用一定低于预算。费用优先级改变预算分配，不改变参考单价或自动产生折扣。初次候选的全行程费用预估、在预算内搜索整份方案的优化器，仍属后续独立工作。

本轮没有修改后端、数据库、共享 DTO、模型 Prompt／schema、token／超时配置、个人环境文件、密钥、原用户数据库或封存数据；没有执行真实校园调用或服务重启。
