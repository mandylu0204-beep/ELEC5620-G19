## 已修复的可观测性缺口

新增 `backend/app/llm/logistics_diagnostics.py`，保持原 JSON 协议、字段约束、工具顺序、Prompt 和身份不变：

- JSON 解析：区分无效 JSON、重复键、非有限数值、递归上限；只记录行／列，不保存原文片段。
- schema 校验：保留字段路径和 Pydantic 错误类型，如 `$.arguments.gear_choices[0].method / literal_error`。
- 已知动作信封只展示对应 Union 分支的错误，避免其他不匹配分支产生大量误导信息。
- 字段路径只允许代码定义的字段名；额外未知字段名统一替换为 `<extra_field>`，避免把恶意／隐私键名写入日志。
- 最多 8 条错误，限制路径深度；不记录 Pydantic 的 input、msg、ctx、URL、用户值、模型原文、Prompt 或密钥。
- 空白理由／摘要保留具体结构位置。
- Agent 在现有错误 context 中补充角色、失败轮次、耗时、响应字节数及累计 HTTP 次数；脱敏结构日志随错误保留，不新增表或独立诊断数据库。
- 原普通用户 HTTP 读取投影继续裁剪内部诊断；内部恢复和授权审核仍保留完整的脱敏错误。`field_errors` 继续为空，避免被公共错误通道直接透出。
- 保持 `CONTRACT_INVALID`、不可自动重试和全部业务守卫；不自动修补／接受非法模型输出，不使用规则冒充模型成功。
