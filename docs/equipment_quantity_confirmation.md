# 装备数量保存与表单入口调整

更新：2026-10-28；基线 main / 1de33e5。保留上一轮需求页模板入口删除的未提交改动。

## 用户确认的交互语义

- 登录页移除示例账户展示；资料页移除“想先体验”及载入样例能力。不删除服务端既有账户或资料。
- 普通装备不再单独勾选拥有状态。用户点击保存资料，即声明填写数量是本次实际可用库存；页面在保存前明确说明。
- 有效非负整数写入原 DTO 的 quantity，confirmed=true；0 表示无库存。空白写入 quantity=null、confirmed=false。数量未知可以保存，不据此假定有库存。
- 未知帐篷容量仍为 null；不以装备可用声明推断容量或清除缺口。非法数量、非法容量和旧错误单位仍按原保存及正式检查处理。
- 后续按用户要求，车辆也移除单独可用确认，显式保存实际车辆数量即声明本次可用；座位数未知仍为未知。历史交通、用餐计划记录保留原确认状态，不因数量自动确认。
- 旧资料有数量但未确认时，允许用户核对后直接保存；仅打开、刷新页面不写入这些确认。放弃修改仍重新读取原保存值。
- 本地字段提示、跳转及烹饪预检查使用拟保存的相同数量语义；预检查不保存资料、不授予正式通过资格。
- 保存新个人资料仍需通过既有预览、采用新 revision、正式检查流程更新方案；旧确认快照、审核、最终记录保持原值。

## 实现边界

转换集中于 frontend/src/equipment_confirmation.ts，并由 ProfilePage 保存路径实际调用。后端继续接收原 Equipment DTO，不改变共享接口、数据库结构或规则身份；其他调用者显式传入 confirmed=false 时仍按未确认处理。无需数据库迁移，不批量改写历史记录。

必填标志统一改为醒目的红色文字标签；后续按用户反馈仅保留小组人数、露营想法、注册等实际需要提示的位置，移除登录及装备名称的新增徽标。数量、容量等原可选资料不新增强制填写要求。
